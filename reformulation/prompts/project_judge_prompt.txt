You are validating whether a rewritten Web3 project description preserves the meaning of the original description while matching an intended view family.

Return strict JSON only.
Do not include markdown.
Do not include explanations outside the JSON.
Do not add extra keys.

You will be given:

* project_name
* original_project_description
* rewritten_project_description
* intended_view_family

The intended_view_family is one of:

* creator_focused
* technical
* skill_focused
* compressed

Scoring rubric:

faithfulness_score:
Score from 1 to 5.
5 means the rewritten description fully preserves the original meaning and contains no unsupported claims.
1 means it changes the project meaning or adds major unsupported claims.

coherence_score:
Score from 1 to 5.
5 means the rewritten description is fluent, readable, and internally clear.
1 means it is confusing, broken, or poorly formed.

relevance_score:
Score from 1 to 5.
5 means the rewritten description stays focused on the original project.
1 means it drifts toward unrelated Web3 concepts, generic marketing text, or irrelevant details.

view_alignment_score:
Score from 1 to 5.
5 means the rewritten description clearly matches the intended view family.
1 means it does not match the intended view family.

View-family definitions:

creator_focused:
The rewrite emphasizes relevant creators, contributors, educators, testers, developers, analysts, advocates, or ecosystem participants while still describing the project.

technical:
The rewrite emphasizes supported protocol, product, infrastructure, mechanism, or implementation-level aspects.

skill_focused:
The rewrite makes relevant expertise areas and contribution areas more explicit while remaining natural and readable.

compressed:
The rewrite is shorter and retrieval-oriented while preserving the project type and distinctive project-specific signals.

Unsupported-claim detection:
List any claims in the rewritten description that are not supported by the original description.
Use an empty list if there are no unsupported claims.
Do not treat reasonable paraphrases as unsupported claims.
Do treat newly introduced technologies, chains, protocols, partnerships, governance, tokenomics, staking, yield, liquidity, privacy, AI, ZK, DeFi, NFT, or gaming claims as unsupported unless clearly present in the original description.

View classification:
Predict the best matching view family from exactly one of:

* creator_focused
* technical
* skill_focused
* compressed

Return exactly this JSON schema:

{
"faithfulness_score": 5,
"coherence_score": 5,
"relevance_score": 5,
"view_alignment_score": 5,
"unsupported_claims": [],
"predicted_view_family": "technical",
"short_reason": "The rewrite preserves the original meaning, stays focused, and matches the intended technical view."
}
